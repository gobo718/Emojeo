GENREACTRIX SERVER AI JOB RUNNER — ONE-TIME CLOUDFLARE SETUP

This release preserves the old browser-run path unless all three server-job bindings exist.

Bindings expected by Worker 0.9.6.139:
  D1 binding:   GENREACTRIX_JOBS_DB
  R2 binding:   GENREACTRIX_AI_IMAGES
  Queue binding: GENREACTRIX_AI_JOB_QUEUE
  Queue name:   genreactrix-ai-jobs

Wrangler path:
1. Install/update dependencies so Wrangler is current.
2. Create the Queue once:
     npx wrangler queues create genreactrix-ai-jobs --config worker/wrangler.toml
3. Deploy normally:
     npx wrangler deploy --config worker/wrangler.toml

The included wrangler.toml declares D1 and R2 as draft bindings, allowing current Wrangler automatic resource provisioning to create/link them during deployment. The Queue is explicitly named and should be created once before the first deploy.

The Worker self-creates its D1 tables on first server-job use; there is no manual SQL migration step.

Dashboard/manual binding path:
- Bind any D1 database as GENREACTRIX_JOBS_DB.
- Bind any R2 bucket as GENREACTRIX_AI_IMAGES.
- Create Queue genreactrix-ai-jobs and bind its producer as GENREACTRIX_AI_JOB_QUEUE.
- Configure this Worker as that Queue's consumer with max batch size 1 and max concurrency 1.

After setup, /api/health should contain:
  serverJobs.enabled: true

If it is false, Genreactrix intentionally keeps using the pre-existing browser-orchestrated AI path.
